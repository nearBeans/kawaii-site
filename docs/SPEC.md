## 1. コンセプト

「情報を読むポートフォリオ」ではなく、**開いた瞬間に可愛さへ入るサイト**。
オリジナルキャラクターが案内役で、画面遷移そのものがコンテンツになる。

- 方向性: ふわふわ・もふもふ・きゃわわ
- 主役: オリジナルちびキャラとワイプ遷移
- 情報量: 少ない。1画面に3〜5個で十分
- やらないこと: ソシャゲの機能、絵本モチーフ、長い文章、スクロールする長いページ
- 既存サイト `https://mofh.dev/` とは**別サイト**。相互リンクはあってよいが、デザインもコードも共有しない

### 役割分担

| 要素 | 質感 |
| --- | --- |
| ワイプ | グラフィック。直線的、フラット、白フチ、パステル |
| キャラ | ふわふわ。丸い、柔らかい、影は1段 |
| 背景 | 静か。クリーム色＋浮遊する小さな図形 |
| UI | 丸いカード、太めの輪郭、押せる感 |

全部をふわふわにするとぼやける。ワイプとUIで締めて、キャラで緩める。

## 2. 画面構成

1画面完結。スクロールしない。下部タブで切り替える。

| タブ | 内容（最小） |
| --- | --- |
| ホーム | 名前、一言、キャラの挨拶、最新ブログ1件 |
| わたし | プロフィールカード、すきなもの3つ |
| つくる | 作品カード2〜3枚 |
| すき | テト、アニメ、旅、音楽などのステッカー |
| つながる | SNSリンク、「お問い合わせ」ボタン → ポップアップ（Formspree のフォーム） |

- タブは5つ。多すぎるとワイプが忙しい。
- 各ページは「見出し＋キャラ＋カード数枚」で完結させる。
- 詳細ページは作らない。カードはその場で少し広がる程度。
- ホームの最新ブログは外部リンクでよい。
- フォームはページに常設せず、「お問い合わせ」ボタンから**ポップアップ**で開く。1画面に収めるための措置。詳細は §2.2。

### 2.1 レイアウト

- モバイル: 全画面。下部タブは親指の届く位置。
- デスクトップ: 中央に 480〜560px の縦長シェル。左右は背景とキャラの余白。
- 上下に固定バーを置く場合も、ワイプは全画面を覆う。
- 下部タブは `env(safe-area-inset-bottom)` を足して、ホームインジケータに重ねない。
- 横向きなど高さが 480px 未満のときは、カードを2列にして1画面に収める（スクロールはさせない）。

### 2.2 お問い合わせポップアップ

- きっかけ: 「つながる」の「お問い合わせ」ボタン。
- 出方: 背景を少し暗くし（`rgba(74, 59, 59, 0.18)`）、中央にカードが**ポンと出る**（キャラ登場と同じばね）。ワイプは使わない。ワイプはタブ切り替えだけのものにする。
- 中身: 名前・返信先メール・本文の3つ＋送信ボタン。ラベルは常時表示。任意項目は作らない。
- 閉じる: ×ボタン、背景タップ、`Esc`。入力があるときは確認を1回はさむ。閉じたら元のボタンにフォーカスを戻す。
- `role="dialog"` / `aria-modal="true"`。フォーカスはポップアップ内に閉じ込める。
- モバイルでキーボードが出たら、カードを上に寄せて送信ボタンを見える位置に保つ（`visualViewport` を監視）。スクロールはカード内だけ許可する。
- 送信は Formspree。成功したら「ありがとう」の一言とキャラの「にこにこ」に差し替える。失敗したらエラー文言と再送ボタン。
- スパム対策はハニーポット1個（視覚的に隠したフィールド）。CAPTCHA は入れない。

### 2.3 オープニング（案・未確定）

- きっかけ: 新しいセッションで**ホーム**を開いたときだけ（`sessionStorage` で判定）。
- タブ移動、戻る／進む、直リンク、リロード、他タブへの直接アクセスでは出さない。
- 内容: 背景 → 中央にちびキャラがポン → サイト名がふわっと上がる → ホームの中身へ。ワイプは使わない。
- 長さ: 1.3秒程度。タップ／キーで即スキップ。
- `prefers-reduced-motion` では出さない。
- サイト名が未定なので、名前の枠だけ用意して仮テキストで実装する。

## 3. ビジュアル

### 形

- 角丸 24〜32px
- 輪郭線 2px（黒ではなく温かい濃茶）
- 影は `0 6px 0 rgba(74, 59, 59, 0.12)` のような硬めの落ち影
- 半透明のツヤ、点描（ハーフトーン）を少量
- ステッカー風の白フチ

### 色（確定: いちごミルク）

| 役割 | 色 |
| --- | --- |
| ベース | `#FFF7F2` |
| メイン | `#FFB3C7` |
| サブ | `#B8E6D9` |
| 差し色 | `#FF8FA3` |

- 文字色は純黒を避け、濃茶（`#4A3B3B` 前後）。
- **タブごとにテーマ色を分けない**。全タブ共通でこの4色を使う。遷移の帯も看板も同じ。
- 色は CSS 変数に集約する。タブ別の色分けを足したくなったら変数1つで切り替えられる形にしておく。
- 却下: ソーダ / よるのラベンダー（履歴としてのみ）

### フォント

- 見出し: Zen Maru Gothic または M PLUS Rounded 1c
- 本文: 上記の本文ウェイト、または Noto Sans JP
- アクセント: DotGothic16（使いすぎない）
- サブセット化して自前ホストする。

- 看板と新ページの見出しを同じ位置・同じ色でつなぐ

## 5. キャラクター

- オリジナルキャラクターを外部に依頼する（**未発注**）。
- 基本は**ちびキャラ1種＋ポーズ差分**で成立させる。遷移もページ常駐も同じちびを使う。
- 立ち絵は「納品物として出てきたら使う」扱い。無くてもサイトは成立する。
- 発注仕様は [CHARACTER.md](CHARACTER.md)。
- 納品前はプレースホルダー（丸い塊＋耳＋目）で実装する。
- パーツ分けされていると、耳・しっぽ・腕・まばたきが動かせる。
- 遷移用に「看板を持つ」「しゃがむ」の差分が必要。

## 6. コンテンツ

最小構成で成立させる。文章は各ページ3行まで。

- ホーム: 名前（mofh / Beans）、一言、時間帯で変わる挨拶
- わたし: 一人称、生年月日（2010-12-06）、居住地（千葉）、学生、すきなもの
- つくる: comic-wiki、JTale、プリント管理アプリなど
- すき: テト、アニメ（百合）、山梨・長野・富士山、音楽

## 7. 技術（確定）

- Vite + React + TypeScript
- Motion（`motion` パッケージ）。遷移レイヤー（帯・キャラ・看板）は CSS の transition / keyframes で実装し、Motion はページ内の小さな動きに使う
- ルーティングは React Router。ただし遷移は TransitionProvider が横取りするので、ルート変更はその中だけで行う
- CSS は素の CSS ＋ CSS 変数（Tailwind は使わない）
- 画像は WebP / AVIF（アルファ対応）、表示サイズの2倍まで
- Cloudflare Pages に静的デプロイ。SPA なので `_redirects` で `index.html` にフォールバックする
- 公開先は `mofh.dev` のサブドメイン（名前は未定）
- フォームは Formspree
- 効果音は **Web Audio API で合成**し、音源ファイルを持たない（MOTION §7）。初期オフ
- 解析は入れない（必要になったら考える）

### 遷移の実装方針

- `TransitionProvider` が `idle / cover / hold / reveal` を持つ
- 遷移中はルート変更をロックし、全面が覆われた瞬間に差し替える
- URL は cover 完了時に `pushState`。戻る／進むは `popstate` を拾って逆方向のワイプにする（MOTION §6）
- 直リンク・リロードはワイプを挟まず即表示
- 次ページの画像はホバー／タッチ開始時に先読み
- キャラはルーターの外に置き、遷移中もアンマウントしない
- 連打はロック。遷移中のタップは早送り

## 8. アクセシビリティ

- `prefers-reduced-motion`: 120ms のフェードのみ
- 遷移後は新しい見出しにフォーカスを移す
- タブはキーボードで移動できる
- 色だけで状態を伝えない
- 効果音は初期オフ。トグルを用意する（BGM は無し）
- 遷移はスキップ可能にする（タップ / キーボードの `Esc`・`Enter`）
- フォームはラベルとエラー文言を明示し、送信内容は最小限にする
- ポップアップは `Esc` で閉じ、開く前の位置にフォーカスを戻す
